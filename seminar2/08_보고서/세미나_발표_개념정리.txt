세미나 발표 핵심 개념 정리
============================================================

1. 파이프라인 전체 흐름
============================================================

[실제 코드 기준 흐름]

원본 사진 → GeoCalib → ① focal length(f_px) 추출
                       ② 왜곡 보정 사진 생성 (ER 비교 실험용)

                       ┌──────────────────────────────────────────────┐
원본 사진 ──────────→ Depth Pro (f_px로 Z 스케일링) → depth map        │
                       → 3D 복원 (핀홀 모델로 X,Y 계산) → RANSAC → 거리│ ← 메인 결과
                       └──────────────────────────────────────────────┘

                       ┌──────────────────────────────────────────────┐
보정 사진 ──────────→ Depth Pro (f_px 입력) → depth map               │
                       → 3D 복원 → RANSAC → 거리                      │ ← ER 비교용
                       └──────────────────────────────────────────────┘

ER = 원본 거리 / 보정 거리 (≈1.0이면 보정 효과 없음)


** 핵심 포인트 **
- GeoCalib의 메인 역할은 "focal length 추정"이지 사진 보정이 아님
- 보정된 사진은 ER 비교 실험을 위해서만 사용됨
- 메인 결과는 "원본 사진 + GeoCalib focal"로 구한 거리


2. Focal Length (초점 거리) - 왜 중요한가
============================================================

[무엇인가]
- 렌즈에서 이미지 센서까지의 거리 (단위: mm 또는 px)
- 작을수록 광각 (넓게 보임), 클수록 망원 (좁게 보임)
- 부동산 사진은 보통 광각 (12~28mm)으로 촬영
  → 공간이 실제보다 넓어 보이는 효과

[왜 필요한가]
- depth map은 "각 픽셀의 깊이(Z)"만 알려줌
- Depth Pro 내부에서 f_px는 Z의 스케일을 결정:
    Z = f_px / (W × canonical_inverse_depth)
- 3D 복원에서도 f_px가 공식에 등장:
    X = (u - cx) × Z / f_px
    Y = (v - cy) × Z / f_px

  (u, v = 픽셀 좌표, cx, cy = 이미지 중심, Z = 깊이)

[중요] 수학적으로 Z에 f_px를 대입하면:
    X = (u - cx) × [f_px / (W × CID)] / f_px
      = (u - cx) / (W × CID)          ← f_px가 약분됨!
    Y도 마찬가지로 f_px와 무관

- 즉, f_px는 X, Y에는 영향을 주지 않고, Z에만 영향을 줌
- f_px가 10% 틀리면 → Z가 10% 틀림 → 벽 거리도 약 10% 틀림
- f_px = 측정 거리의 "축척(스케일)"을 결정하는 핵심 변수

[문제]
- 부동산 플랫폼(직방, 네이버)이 업로드 시 EXIF를 삭제
- EXIF에 포함된 focal length 정보가 사라짐
- → GeoCalib으로 이미지만 보고 추정해야 함


3. Focal Length가 쓰이는 정확한 위치
============================================================

f_px는 코드상 2곳에 등장하지만, 수학적으로는 Z 스케일링 1가지 역할만 함:

[코드에 등장하는 2곳]

(1) Depth Pro 내부 - Z 스케일 변환
  Depth Pro 소스코드 (depth_pro.py, 281~293줄):

    canonical_inverse_depth, fov_deg = self.forward(x)   # 신경망 예측 → f_px와 무관
    inverse_depth = canonical_inverse_depth * (W / f_px)  # f_px로 스케일링
    depth = 1.0 / torch.clamp(inverse_depth, min=1e-4, max=1e4)

  - canonical_inverse_depth(CID)는 f_px와 독립적 (신경망이 예측)
  - f_px는 이것을 "실제 미터 단위 Z"로 변환: Z = f_px / (W × CID)
  - f_px가 없어도 depth map의 "패턴"(어디가 가깝고 먼지)은 동일

(2) 3D 복원 - X, Y 좌표 계산 (코드 88~89줄)

    X = (u - cx) × Z / f_px
    Y = (v - cy) × Z / f_px

[수학적 실체: f_px는 X,Y에서 약분됨]

  Z = f_px / (W × CID) 를 대입하면:

    X = (u - cx) × [f_px / (W × CID)] / f_px
      = (u - cx) / (W × CID)           ← f_px 사라짐

    Y = (v - cy) / (W × CID)           ← f_px 사라짐

  → X, Y는 f_px와 무관. Z만 f_px에 비례.
  → f_px가 10% 틀리면 Z가 10% 틀리고, 벽 거리도 약 10% 틀림.
  → f_px는 결국 "측정 결과의 축척(스케일)"을 결정하는 단일 변수.

** 핵심: f_px는 최종 측정 거리에 선형 비례하는 스케일 팩터.
   코드상 2곳에 나타나지만 수학적으로 X,Y에서는 약분되어
   실질적으로 Z(깊이)의 스케일만 결정함. **


4. GeoCalib (ECCV 2024, ETH Zurich)
============================================================

[하는 일]
- 이미지만 보고 focal length + 왜곡 파라미터를 추정

[원리]
- 실내 사진에는 수직선(벽 모서리), 수평선(바닥-벽 경계)이 많음
- 광각 렌즈로 찍으면 이 직선들이 휘어짐 (barrel distortion)
- GeoCalib은 CNN으로 이 기하학적 단서를 학습해서
  역으로 focal과 왜곡 정도를 추정

[코드에서의 역할]
  gc_model = GeoCalib(weights='distorted')     # 왜곡 가중치 로드
  result_gc = gc_model.calibrate(img_gc)        # 캘리브레이션 실행
  f_wide = camera.f.mean().item()                # focal length 추출
  undistorted = camera.undistort_image(img_gc)   # 왜곡 보정 이미지 (ER 비교용)

[발표 포인트]
- GeoCalib은 focal 추정 + 왜곡 보정 두 가지를 동시에 해줌
- 본 연구에서는 focal 추정이 핵심, 왜곡 보정은 부가 실험


5. Depth Pro (Apple, ICLR 2025)
============================================================

[하는 일]
- 단일 이미지 → metric depth map (실제 미터 단위 깊이)

[왜 특별한가]
- 기존 depth 모델(MiDaS 등)은 "상대 깊이" (어디가 가깝고 먼지만)
- Depth Pro는 "절대 깊이" (이 점이 카메라에서 정확히 3.2m)
  → 실제 거리 측정이 가능해짐

[코드에서]
  pred_orig = dp_model.infer(dp_transform(img_orig), f_px=torch.tensor(f_wide))
  depth_orig = pred_orig["depth"].detach().cpu().numpy()

  - f_px를 함께 입력하면 정확한 metric depth 생성
  - f_px 없이도 동작하지만, 자체 추정 focal을 사용하므로 덜 정확


6. RANSAC 벽 측정 - 어떻게 벽을 찾나
============================================================

[RANSAC (RANdom SAmple Consensus)]
1. 3D 점 중 랜덤 3개를 뽑아 평면을 만듦
2. 그 평면에 가까운 점(inlier)이 얼마나 많은지 확인
3. 1000번 반복, 가장 inlier 많은 평면이 "벽"
4. 찾은 평면의 점들을 제거하고 다음 벽 탐색 (최대 6번)

[벽 판별 기준] (코드 105줄)
  if abs(nm[1]) <= 0.7:  # 수직 벽만 (바닥/천장 제외)

  - 법선 벡터(nm)의 Y성분이 0.7 이하 → 수직 벽
  - 바닥은 Y=1이므로 자동 제외, 천장도 마찬가지

[벽 거리 계산] (코드 111~118줄)
  - 두 벽의 법선이 서로 평행 (dot product > 0.8)하면 벽 쌍으로 인식
  - 두 평면 방정식의 d값 차이 = 벽-벽 수직 거리 (미터 단위)
  - 이것을 × 1000 → mm 단위로 변환


7. GT (Ground Truth) 보정
============================================================

  gt_adj = gt_mm - 160  (코드 201줄)

- 네이버 부동산 도면은 "벽 중심선" 기준 (콘크리트 구조체 중심)
- 실제 실내 거리는 "마감면" 기준 (벽지/타일 표면)
- 벽 두께 약 160mm (양쪽 각 80mm) 차감하여 보정
- 한계: 실제 벽 두께는 단지마다 ±40mm 차이 존재


8. ER (Barrel Distortion 보정 효과)
============================================================

  ER = D_wide(원본 거리) / D_corrected(보정 거리)

- ER ≈ 1.0이면 보정 효과 없음
- 실험 결과: 중앙값 0.998, 범위 0.935~1.038
- 결론: Depth Pro가 이미 barrel distortion에 robust하므로 보정 불필요

[비교]
- Buquet et al. (2021, CVPR Workshop): "보정 시 5% 개선"
- 하지만 그때는 구형 모델 사용. 최신 MMDE(Depth Pro)에서는 효과 없음


9. Propix (2024) 대비 확장점
============================================================

[Propix가 한 것]
- GeoCalib으로 부동산 사진의 왜곡 탐지 (focal length 추정)
- "이 사진은 광각으로 왜곡됨" 판별만 수행
- 논문에서 "왜곡률 기준값 도출을 위한 연구가 진행 중"이라 명시
- → 실제 거리 측정은 하지 않음

[본 연구가 확장한 것]
1. Propix의 GeoCalib focal → Depth Pro에 입력하여 실제 depth map 생성
   (Propix는 여기까지 안 함)
2. Depth map → 3D 복원 + RANSAC으로 벽-벽 거리 실측
   (Propix는 거리 측정 없음)
3. 평면도 GT와 정량 비교 (83장, 6개 단지) → 정확도 검증
4. GeoCalib focal vs Depth Pro 자체 추정 비교 실험
   → 광각에서 GeoCalib이 우수함 입증

[한 줄 요약]
Propix = "왜곡 탐지까지" → 본 연구 = "왜곡 탐지 + 실제 거리 측정 + GT 검증"

11. 발표에서 질문 받을 수 있는 포인트
============================================================

Q: "왜 Depth Pro만 썼나?"
A: 현재 유일한 metric depth 오픈소스 모델.
   Metric3D V2, UniDepth V2도 있지만 비교는 향후 과제.

Q: "왜 벽 두께를 160mm로 고정했나?"
A: 일반적인 아파트 벽 두께. 단지마다 ±40mm 차이가 있어
   GT 불확실성 존재. 이것이 한계점 중 하나.

Q: "RANSAC이 벽 아닌 걸 잡으면?"
A: 가구, 아일랜드 등이 벽으로 잡힐 수 있음.
   이것이 장애물 있는 사진에서 오차가 큰 이유.
   → 장애물 있으면 평균 24.5% 오차.

Q: "상용화 가능한가?"
A: 양호 조건 79%가 10% 이하 오차. 참고용으로는 가능하나,
   법적 기준(±5cm 등)에는 미달. 추가 연구 필요.

Q: "GeoCalib 없이 Depth Pro만 쓰면 안 되나?"
A: Depth Pro도 자체 focal 추정 가능하지만,
   광각에서 GeoCalib이 더 정확 (4%p 차이).
   광각이 아닌 일반 사진에서는 비슷함.

Q: "보정된 사진을 쓰면 더 좋지 않나?"
A: ER ≈ 1.0으로 보정 효과가 거의 없음.
   Depth Pro가 이미 왜곡에 robust하기 때문.
